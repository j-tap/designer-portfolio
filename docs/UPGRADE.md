# План обновления: Strapi 5, Nuxt 4, Node 24

Ветка: `upgrade/strapi5-nuxt4`. Пуш в `main` сразу деплоит на прод (`.github/workflows/deploy.yml`),
поэтому работа идёт в ветке, а в `main` она попадает только после проверки и бэкапа на сервере
(см. «Выкатка»).

## Зачем

- **Node 20** снят с поддержки в апреле 2026, а Nuxt 4.6 его уже не поддерживает → **Node 24 LTS**.
- **Strapi 4** больше не получает обновлений безопасности → **Strapi 5**.
- **Nuxt 3** в режиме поддержки, модули (i18n, sitemap, pinia) выпускают новые версии только под Nuxt 4.
- Часть плагинов Strapi заброшена с 2022–2023 годов и под v5 не существует.

## Что меняется в бэкенде и чем заменяется

| Было (v4) | Под v5 | Решение |
|---|---|---|
| `strapi-plugin-transformer` (убирает `attributes`/`data`) | не нужен: ответ v5 и так плоский | удалить; верхний `data` остаётся, как и сейчас |
| `strapi-plugin-populate-deep` (`populate=deep`) | есть только сторонний плагин, который подставляет populate в обход проверки прав REST | свой middleware: `populate=deep` → объект populate по схеме, дальше штатная валидация Strapi |
| `strapi-plugin-slugify` | нет версии под v5 | поле `slug` → тип `uid` с `targetField: title` (генерация в админке встроена в Strapi); колонка та же, данные сохраняются |
| `strapi-blurhash` 1.x | 2.0 тянет нативный `canvas` и качает картинки по HTTP | своя реализация на `sharp` + `blurhash`; атрибут `blurhash` у файлов сохраняется, иначе синхронизация схемы удалит колонку с 695 готовыми хешами |
| `strapi-provider-email-smtp` (2022) | — | `@strapi/provider-email-nodemailer` с теми же настройками TLS |
| `@strapi/plugin-i18n`, `@strapi/plugin-email` | встроены в ядро | удалить из зависимостей |
| `@retikolo/drag-drop-content-types` 1.x | 2.x | обновить |
| `strapi-plugin-multi-select` 1.x | 2.x | обновить |
| `@strapi/plugin-color-picker` 4 | 5 | обновить |
| свой плагин `relations-select` | — | удалить: это заготовка с тестовым пунктом «TEST», ни одна схема его не использует |

Изменения в коде отзывов:

- В v5 больше нельзя загружать файлы вместе с созданием записи (`files.files` в multipart):
  файлы сначала загружаются через сервис upload, потом их id указываются в записи.
- `lifecycles.afterCreate` в v5 срабатывает и при публикации черновика (публикация создаёт
  новую строку) — письмо о новом отзыве приходило бы дважды. Письмо уходит из контроллера.
- `publicationState=live` → `status=published`.
- Связи (`developments`, `cooperations`) задаются по `documentId`; фронт отправляет `documentId`.
- Ссылка на отзыв в письме — по `documentId` (так устроены адреса в админке v5).

Миграцию данных (`document_id`, черновики/публикации, связи локалей) Strapi 5 выполняет сам при
первом запуске. Перед этим обязательна копия `backend/.tmp/data.db` и `backend/public/uploads`.

## Что меняется во фронтенде

- Nuxt 4: структура каталогов остаётся прежней (в корне `frontend/`, Nuxt 4 её поддерживает);
  `process.client` → `import.meta.client`; убраны несуществующая опция `mode` и дубль
  `compatibilityDate`; `"type": "module"` в package.json (конфиги — ES-модули).
- `nitro.publicAssets` для `/_nuxt/` удалён: в Nuxt 4 путь считается от `server/`, папки нет,
  и Nuxt предупреждал, что `/_nuxt/**` начнёт отдавать 404. Кеш на год для `/_nuxt` Nuxt ставит
  сам, плюс заголовки из `routeRules`.
- `prerender: true` у `/portfolio` удалён: при стратегии i18n `prefix` такой страницы нет
  (только `/<locale>/portfolio`), Nuxt 3 молча сохранял в статику страницу 404, Nitro в Nuxt 4
  падает на этом при сборке. Данных Strapi при сборке в Docker всё равно нет.
- i18n 10: `iso` → `language`, переводы — в `i18n/locales`, настройки vue-i18n —
  `i18n/i18n.config.js` (импорты через `~/`: i18n собирает файл и для сервера);
  глобальный `localePath` в шаблонах убран — в 5 компонентах добавлен `useLocalePath()`.
- unhead 2: `children` в `useHead` устарел → `innerHTML` (JSON-LD экранируется самим unhead).
- Карта сайта: убран `populate[]=updatedAt` (в v5 — 400), раскрыт `subcategories.category`
  (код строит из него адрес, но v4-запрос его не получал — карта упала бы при первой
  подкатегории), лимит 100 вместо 25 по умолчанию: раньше в ru-карту не попадали 9 проектов.
- Форма отзывов отправляет `documentId` направлений и язык страницы.
- Удалены прямые зависимости `vite`, `unhead`, `@nuxt/devtools` (их приносит Nuxt нужных версий),
  добавлены `vue`/`vue-router` (как в шаблоне Nuxt 4) и `zod` (peer у sitemap 9).

## Как проверяем, что ничего не сломалось

До начала работ на копии БД сняты эталоны текущей версии (Strapi 4 + Nuxt 3):

1. **API** — ответы Strapi на все запросы, которые делает фронт (105 запросов: каждая локаль,
   категория, проект, отзывы, контакты, запросы карты сайта).
2. **Страницы** — SSR-HTML 88 адресов: главная, портфолио, все категории и проекты в ru/en,
   отзывы, контакты, донат, визитка, robots.txt, карта сайта. Из HTML извлекаются заголовки,
   мета-теги, JSON-LD, ссылки, картинки и видимый текст.

После каждого этапа те же снимки делаются с новой версии и сравниваются с эталоном. Допустимые
отличия: новое поле `documentId`, служебные поля (`publishedAt`) и хеши сборки.
Отдельно проверяются вручную: админка (вход, редактирование, drag-drop сортировка, multi-select,
color picker, генерация slug, загрузка картинки → blurhash), отправка отзыва с файлами и письмо.

## Решения

- **Strapi 5.57.0, а не 5.58.0.** 5.58.0 вышел в день работ; Yarn 4.18 по умолчанию не ставит
  пакеты моложе суток (`npmMinimalAgeGate`), и это разумная защита от взломанных релизов.
  Исправления безопасности из 5.58 (axios 1.20, handlebars 4.7.10, sharp 0.35.5) подключены
  через `resolutions`. Переход на 5.58+ — обычным `yarn up` через неделю-другую.
- **Yarn 4.18**: install-скрипты сторонних пакетов выключены по умолчанию. Разрешены только
  нужные через `dependenciesMeta` (`better-sqlite3` — нативная сборка, `esbuild`, `@swc/core`).
- **Фронтенд, `yarn npm audit`**: `simple-git` (critical) приходит только из `@nuxt/devtools`
  3.4.2 — dev-инструмент, в прод-сервер не попадает. В devtools 3.4.3 зависимость убрана, но он
  вышел в день работ (карантин Yarn); `simple-git` 4 через `resolutions` ломает devtools.
  **После 2026-10-15 выполнить `yarn up -R @nuxt/devtools` во `frontend/`.** Остальное
  (`node-forge` в dev-сервере listhen, `braces`, `glob`) исправленных версий не имеет.
- **Бэкенд, остаточные предупреждения `yarn npm audit`** (исправленных совместимых версий нет):
  `braces` через chokidar (вотчер файлов в `develop`), `react-router` 6 (админка Strapi требует
  именно v6), `stream-json` 1.x (перенос данных, выключен без `TRANSFER_TOKEN_SALT`), устаревшие
  `glob`/`rimraf`/`inflight`/`prebuild-install`/`@koa/router` внутри Strapi. Уйдут с обновлениями Strapi.

## Проверка Docker-образов

Образы собраны теми же Dockerfile, что использует деплой (`node:24-alpine`), и запущены как
на проде, на свежей копии исходной БД Strapi 4:

- Strapi 5.57 на Node 24.21 при старте мигрировал БД, `better-sqlite3` и `sharp` под Alpine
  работают (отзыв с картинкой сохранился, blurhash посчитан);
- API — те же 101 из 104 совпадений с эталоном; страницы — 85 из 86 идентичны (индекс карты
  сайта отличается только комментарием генератора);
- браузерный прогон — как локально.

Два наблюдения про часовой пояс (было и до обновления, код не менялся): контейнер работает в
UTC, а даты (`time.start` проектов, дата отзыва) форматируются и на сервере, и в браузере —
у посетителя западнее UTC дата при гидратации меняется на предыдущий день, Vue пишет
предупреждение о расхождении гидратации.

## Выкатка на прод

Переменные в `.env` на сервере менять не нужно: новые `ENCRYPTION_KEY` и `TRANSFER_TOKEN_SALT`
необязательны (без `ENCRYPTION_KEY` токен API виден только при создании).

1. На сервере остановить Strapi и сделать бэкап (БД и загрузки лежат в bind-mount, в образ
   не попадают). Остановка нужна, чтобы копия SQLite была целостной; сайт без Strapi
   работает до конца выкатки только из кеша, поэтому лучше делать в тихое время:
   ```sh
   cd <проект>
   docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.traefik.yml stop strapi
   tar czf ~/backup-$(date +%F).tgz backend/.tmp backend/public/uploads .env
   ```
2. Влить ветку в `main` → GitHub Actions выполнит `git pull && make prod` (соберёт образы на
   Node 24 и перезапустит контейнеры).
3. При первом запуске Strapi 5 мигрирует БД (на текущем объёме — меньше секунды). Проверить:
   `docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.traefik.yml logs -f strapi` —
   строки `[internal migration]` без ошибок и `Strapi started successfully`.
4. Проверить вручную:
   - главная, портфолио, проект, отзывы, контакты, донат, визитка в ru/en; `/sitemap_index.xml`;
   - админка: войти заново (сессии Strapi 4 недействительны), открыть и сохранить проект,
     создать черновик проекта и проверить генерацию slug, перетащить элемент в Drag Drop,
     загрузить картинку в медиатеку;
   - отправить отзыв с картинкой с сайта и **убедиться, что пришло письмо** — настоящий SMTP
     (STARTTLS/465) можно проверить только на сервере; затем опубликовать отзыв в админке.

**Откат:** вернуть код на предыдущий коммит (`git revert` мерж-коммита в `main` или
`git reset --hard <коммит>` на сервере), **восстановить `backend/.tmp` из архива**, `make prod`.
Восстановление БД обязательно: Strapi 4 не умеет читать базу, мигрированную Strapi 5.

**Локальная разработка:** первый `make dev` / `yarn develop` так же необратимо мигрирует
локальную `backend/.tmp/data.db` — перед этим стоит сохранить её копию.

## Чистка после обновления

После выкатки код прошёл аудит на костыли, дублирование и баги (ветка `fix/portfolio-404`).

Бэкенд:

- `proxy: true` в `config/server.js` Strapi 5 молча игнорирует (читается только `proxy.koa`): за Traefik
  IP посетителя не определялся, лимит отзывов был общим на всех, cookie админки уходила без `Secure`.
- Удалён `redirector`: `GET /` в адрес админки с учётом `/strapi` ведёт штатный `strapi::public`.
- Роутеры открывают только нужные сайту действия (`only`), а не все — включая `update`/`delete`,
  защищённые до этого одной галочкой в правах роли Public.
- Отзывы: штатные ошибки Strapi (`ValidationError`, `RateLimitError`) вместо своих классов, письмо
  не задерживает ответ (и таймауты SMTP), файлы удаляются, если отзыв не сохранился, лимит
  считается после проверки полей, ссылка `site.ru:8080` больше не принимается за схему.
- Убраны неработающий переключатель на Postgres и `pg`, мёртвые конфиги и шаблонный README;
  исправлены перепутанные ru/en приветствия админки.

Фронтенд:

- Данные — `useStrapiData` (обёртка над `useAsyncData` + `useStrapi`) вместо пяти своих функций:
  ошибки Strapi больше не превращаются в пустые страницы со статусом 200, данные при переходах
  по сайту перезапрашиваются, язык входит в ключ кеша. Нет записи — 404, сбой Strapi — 500.
- Портфолио: пять страниц и middleware → три страницы (`[category]`, `[category]/[slug]`,
  `[category]/[slug]/[project]`) на общих `useProjectPage` / `usePortfolioListPage`.
- SEO: canonical, hreflang, `og:locale` — штатный `useLocaleHead`; заголовок/описание — `usePageMeta`
  на `useSeoMeta`; JSON-LD регистрируется в `useStructuredData` (без восьми копий `watch` + `useHead`,
  из-за которых у страниц проектов при SSR не было JSON-LD, а при переходах он копился).
  Исправлены: «Сайт | Сайт» в заголовке главной, 404 с заголовком сайта вместо «404»,
  `og:image` на адрес сайта вместо Strapi.
- Pinia удалена: store заменены `useState`, `useSiteMeta`, `useLocalStorage`; самодельные индикатор
  загрузки, прокрутка, `useMedia`, `useEventListener` — на штатные Nuxt/vueuse.
- Исправлены баги из списка ниже (кроме `rank` и Sass), а также: нижняя картинка веб-проекта не
  показывалась никогда, внешние ссылки проекта шли через `localePath` (без защиты от `javascript:`),
  RU-тексты формы отзывов на en/es, утечка `blob:`-превью файлов, параллакс на трёх копиях
  обработчика прокрутки, перенаправление категории на подкатегорию работало только при переходе
  по сайту (теперь middleware, 302 с сервера).
- «Ещё проекты» — 15 самых новых проектов категории (раньше — первые 15 в порядке базы).

## Повторная проверка

Код ещё раз проверен на дублирование, баги и уязвимости, сайт сверен со сборкой до правок: все 73 страницы
из карты сайта (кроме постов, они проверены выборочно) отдают те же статусы, заголовки, мета-теги,
JSON-LD и ссылки; в браузере переходы по сайту без ошибок в консоли.

- **Уязвимость: временные файлы.** `strapi::body` сохраняет в `/tmp` файлы любого multipart-запроса
  ещё до проверки маршрута и прав, а удаляет только поле `files`. Анонимный запрос на любой адрес
  (`POST /strapi/api/что-угодно` с файлом в поле `x`) оставлял файл навсегда, и так можно было
  заполнить диск (в проде `/tmp` — это `backend/tmp` на хосте). Теперь всё удаляет middleware
  `cleanup-uploads`; своя очистка в контроллере отзывов больше не нужна. **На сервере один раз
  очистить `backend/tmp`** от накопившихся файлов.
- Убран заголовок `X-Powered-By: Strapi` (`strapi::poweredBy`).
- Мета-информация запрашивалась у Strapi 2–4 раза на каждую страницу: у `useAsyncData` по умолчанию
  `dedupe: 'cancel'`, а на сервере каждый вызов с тем же ключом загружает данные заново.
  `useStrapiData` теперь отдаёт идущий или уже выполненный в этом запросе страницы запрос — один
  запрос на страницу.
- Адрес страницы проекта строится одной функцией `projectPath` (список категории, «Ещё проекты»,
  карта сайта). «Ещё проекты» на странице проекта в подкатегории теперь ведут в ту же подкатегорию.
- Без дублей: название сайта — `useSiteName`, экранирование в RSS — общий `escapeHtml`,
  `Cache-Control` для robots.txt и RSS — только в `routeRules`; активный пункт меню определяется
  через `localePath`, а не регуляркой с двухбуквенными кодами языков.
- Страница поста: id экранируется в запросе к API, ненайденный пост при переходе по сайту
  открывает страницу 404 (как остальные страницы), удалён недостижимый блок «Пост не найден».
